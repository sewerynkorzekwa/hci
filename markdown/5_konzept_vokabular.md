# Vokabular: Konzept-Workshop

## Szenarien

| Begriff | Definition |
|---|---|
| **Szenario** | Narrative Beschreibung einer handelnden Person, ihres Ziels und des Kontexts; abstrahiert von gestalterischen Details; macht zukuenftige Nutzungssituationen erlebbar |
| **Happy Case** | Typischer, reibungsloser Ablauf eines Szenarios ohne Sonderfaelle; Ausgangspunkt der Konzeptarbeit |
| **Edge Case** | Sonderfall oder Ausnahmefall in einem Szenario; wird erst nach dem Happy Case betrachtet |
| **Soll-Szenario** | Zukunftsorientiertes Szenario, das die angestrebte Zielvorstellung beschreibt; bildet Grundlage fuer die Ableitung von Funktionalitaeten |

## User Story Mapping

| Begriff | Definition |
|---|---|
| **User Story Map** | Visualisierung der Aufgaben, die User bei der Erreichung ihrer Ziele in wesentlichen Szenarien bewaeltigen; zweiachsige Darstellung (horizontal = sequenzieller Ablauf, vertikal = Ziel + Aufgaben + Teilaufgaben) |
| **User Story** | Ein oder zwei alltagssprachlich formulierte Saetze, die konkrete Bearbeitungsaufgaben beschreiben; allgemeines Format: »Als \<Persona\> muss ich bei der \<Zielerreichung\> eine \<Aufgabe\> durchfuehren, weil \<Begruendung\>.« |
| **Teilaufgabe** | Detaillierte Variante oder Alternative einer Aufgabe in der User Story Map; hoeherer Detaillierungsgrad; Hoehe der Platzierung reflektiert Priorisierung |
| **Zielsetzung** | Uebergeordnetes Ziel in der User Story Map (z.B. »Leistungen erfassen«); bildet den Rahmen fuer alle darunter angeordneten Aufgaben |

## Wireflows und Sketching

| Begriff | Definition |
|---|---|
| **Wireflow** | Visualisierung des Flusses von Interaktionen durch miteinander verknuepfte Wireframes; zeigt involvierte Screens, notwendige Aktionen und Zustandsaenderungen des Interface |
| **Wireframe** | Konzeptioneller Entwurf eines Screens als konkretisierte Layoutdarstellung; legt Groesse, Position und raeumliche Bezuge der zentralen Bereiche sowie Interaktions- und Navigationselemente fest; abstrahiert von visuell-aesthetischer Ausgestaltung |
| **Sketching** | Freihaendiges Zeichnen von Interface-Konzepten auf Papier; bietet Freiheitsgrade und Geschwindigkeit; foerdert kreatives Erkunden des Loesungsraums ohne Einschraenkung durch digitale Tools |

## Framework und Keyscreens

| Begriff | Definition |
|---|---|
| **Framework** | Grobe Skizze der Ablaeufe, in der Inhalte und Funktionalitaeten einzelnen Screens zugeordnet werden; legt relevante Interaktionskontexte fest; Basis ist die User Story Map |
| **Keyscreen** | Wichtigster Screen des zukuenftigen Interface; wird im Konzept-Workshop detailliert ausgearbeitet; zeigt Daten, Funktionen und deren raeumliche Anordnung |
| **Design Pattern** | Bewaehrte Loesung fuer wiederkehrende Gestaltungsprobleme (z.B. Kalender-Pattern oder Spreadsheet-Modus); hilft bei der Wahl geeigneter Interaktionskonzepte im Framework |
| **Label** | Inhaltlich aussagekraeftiger Bezeichner in einem Wireframe (kein Blindtext); ermoeglicht Bewertung von Verstaendlichkeit und Platzbedarf |
