# Vokabular: Synthese-Workshop

## Personas

| Begriff | Definition |
|---|---|
| **Proto-Persona** | Hypothetischer archetypischer User basierend auf Annahmen des Projektteams; nicht empirisch belegt |
| **Validierte Persona** | Durch empirische Daten (Nutzerforschung) belegte und ueberpruefte Persona; ersetzt Proto-Persona |
| **Evidenzbasierte Personas** | Personas, die auf Grundlage empirischer Forschungsergebnisse erstellt werden; z.B. durch Pattern-Analyse nach Salazar (4 Schritte) |
| **Konsolidierung** | Zusammenfuehrung mehrerer Proto-Personas zu einer einzigen Persona, wenn die Daten keine Unterscheidung stuetzen |
| **Latente Klassenanalyse** | Statistisches Verfahren zur Identifikation von Mustern in kategorialen Daten; Alternative zur visuellen Pattern-Inspektion bei grossen Stichproben |

## Evidenzbasierung (4 Schritte nach Salazar)

| Begriff | Definition |
|---|---|
| **Empirische Studie** | Schritt 1: Durchfuehrung einer Untersuchung, um bedeutsame Merkmale der Nutzer tatsaechlich kennenzulernen |
| **Merkmalsidentifikation** | Schritt 2: Bestimmung, welche Merkmale von Nutzenden fuer das Design entscheidend sind |
| **Codierung** | Schritt 3: Zuordnung von festgestellten Merkmalsauspraegungen zu definierten Kategorien; iterativer Prozess |
| **Pattern-Identifikation** | Schritt 4: Suche nach uebergreifenden Mustern in den Merkmalskombinationen, die auf unterschiedliche Persona-Typen hinweisen |
| **Merkmalskombination** | Kombination von Auspraegungen verschiedener Merkmale, die als zusammenhaengendes Muster (Strang/Pfad) erkennbar wird |

## Modelle und Synthese-Artefakte

| Begriff | Definition |
|---|---|
| **Modell** | Reduzierte, vereinfachende Beschreibung der Wirklichkeit; stellt bedeutsame Aspekte in den Vordergrund und laesst Irrelevantes weg |
| **Journey Map** | Visualisierung des beobachteten Ablaufs zur Erreichung eines Ziels einer Persona; dokumentiert Schritte, Findings und Mengengerueste |
| **Insight Statement** | Auf Ergebnissen der Nutzerforschung basierende Aussage, die fuer die Produktentwicklung wesentliche, fuer das Team neue und bedeutsame Einsichten benennt |
| **Opportunity Area** | Produkt- oder Servicebereich mit vermutetem Verbesserungspotenzial; Chance zur Optimierung, abgeleitet aus Erkenntnissen der User-Research-Aktivitaeten |
| **Mengengeruest** | Quantitative Angaben zu Haeufigkeiten von Taetigkeiten und Anzahl erfasster Daten in der Journey Map |

## Problem Reframing

| Begriff | Definition |
|---|---|
| **Proto-Problem Statement** | Im Scoping-Workshop formulierte, auf Annahmen basierende Problemdefinition mit Nutzenden, Problemen, Loesungsansaetzen, Metriken, Stakeholdern, Randbedingungen und Risiken |
| **Revidiertes Problem Statement** | Ueberarbeitetes Problem Statement auf Basis empirischer Erkenntnisse aus der Nutzerforschung; kann neue Nutzergruppen, Probleme, Metriken und Stakeholder enthalten |
| **Benchmark** | Empirisch gesicherter, quantitativer Vergleichswert, der den folgenden Designaktivitaeten eine klare Orientierung gibt (z.B. weniger als 6 Minuten pro Tag fuer Leistungserfassung) |
| **Problem Reframing** | Prozess der Ueberarbeitung und ggf. grundlegenden Revision des urspruenglichen Proto-Problem Statement im Lichte empirischer Erkenntnisse |
| **Metrik (im Kontext Synthese)** | Messbarer Zielwert, der im Problem Statement festgelegt wird und durch empirische Daten gestuetzt sein sollte (z.B. Unterschreitung von 6 Minuten pro Tag) |
