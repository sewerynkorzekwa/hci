## 10. Vorgehenmodell - Menschen zentriert (ISO, Collaborative UX Design)

**Kurzbeschreibung:**
Ein menschzentriertes Vorgehensmodell (wie ISO 9241-210 / Collaborative UX Design) integriert Nutzende iterativ in den Gestaltungsprozess. Es besteht aus mehreren Workshops und unterscheidet zwischen Problemraum (Verstehen), Lösungsraum (Erkunden) und Umsetzung (Delivery).

## 22. Die Phasen und Artefakte im Collaborative UX Prozess

**Kurzbeschreibung:**
Der Collaborative UX Prozess gliedert sich in **3 Phasen**:
1. **Verstehen (Problemraum)**: Scoping, Research, Synthese → Problem Statement Map, Proto-Personas, Proto-Journey, Annahmen-Map
2. **Erkunden (Lösungsraum)**: Ideation, Konzept, Prototyping, Validierung, Roadmap → Prototypen, User Journeys, priorisierter Ideenkatalog
3. **Delivery (Umsetzung)**: Agile Sprints → Release, MVP (oft in Grafiken vergessen)

## 34. UX Workshop Ablauf und jeweils ein Artefakt

**Kurzbeschreibung:**
Jeder der 8 Collaborative-UX-Workshops hat einen definierten Ablauf und produziert spezifische Artefakte:

| Workshop | Zweck | Artefakte |
|----------|-------|----------|
| **Scoping** | Ziele, Annahmen klären | Problem Statement Map, Proto-Personas, Proto-Journey, Annahmen-Map |
| **Research** | Annahmen validieren | Forschungsergebnisse, Interviews-Protokolle |
| **Synthese** | Ergebnisse analysieren | Personas (empirisch fundiert), User Stories, Anforderungen |
| **Ideation** | Ideen generieren | Priorisierter Ideenkatalog |
| **Konzept** | Lösungskonzept skizzieren | User Journey, Wireframes |
| **Prototyping** | Prototyp ausarbeiten | Prototyp (verschiedener Fidelität) |
| **Validierung** | Konzept testen | Testergebnisse, Severity Levels |
| **Roadmap** | Releases planen | MVP-Definition, Priorisierung, Metrikenboard |

**Quelle:**
- Kapitel 0_einleitung.md: Abschnitt "Das Vorgehensmodell" (detaillierte Beschreibungen der einzelnen Workshops)

## 35. Unterschied zwischen Sketches und Wireframes

**Kurzbeschreibung:**
- **Sketches**: Schnelle, handgezeichnete oder digitale Entwürfe mit niedriger Fidelität; dienen der Ideenfindung und Kommunikation von groben Konzepten; wenig Detail, schnell zu erstellen
- **Wireframes**: Strukturelle Darstellungen der Benutzeroberfläche mit mittlerer Fidelität; zeigen Layout, Information Architecture, Navigationselemente; mehr Detail als Sketches, aber ohne visuelles Design

- Klausurfragen Kap. 0: Implizit über Prototypen-Fidelität

## 36. Unterschied zwischen Stakeholder und User

**Kurzbeschreibung:**
- **User/Nutzer**: Endbenutzer, die das Produkt tatsächlich verwenden; ihre Bedürfnisse und Ziele stehen im Fokus der Gestaltung
- **Stakeholder**: Alle beteiligten Parteien (Manager, Auftraggeber, Entwickler, Geschäftsführung, etc.); haben oft unterschiedliche, teilweise konfligierenden Anforderungen und Ziele

**Wichtig:** Menschzentriertes Design balanciert diese widersprüchlichen Anforderungen: Bedürfnisse von Nutzenden UND technische Rahmenbedingungen UND wirtschaftliche Geschäftsziele.
