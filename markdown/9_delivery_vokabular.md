# Vokabular – Kapitel 9: Delivery

---

## Agile Grundbegriffe

| Begriff | Definition |
|--------|-----------|
| **Sprint** | Kurzer, zeitlich begrenzter Entwicklungszyklus (typischerweise 1–4 Wochen); am Ende steht ein potenziell lieferbares Produktinkrement |
| **Product Backlog** | Gesamtmenge aller priorisierten User Stories für ein Produkt; wird laufend gepflegt |
| **Sprint Backlog** | Teilmenge des Product Backlogs; User Stories, die für einen konkreten Sprint geplant wurden |
| **Story Points** | Relatives Maß für den Aufwand einer User Story; kein Zeitwert, sondern Vergleichsgröße zwischen User Stories |
| **Velocity** | Erreichbare Arbeitsmenge (in Story Points), die ein Team realistisch in einem Sprint leisten kann; Grundlage für die Sprintplanung |
| **Epic** | Größeres Funktionsinkrement, das sich aus mehreren zusammenhängenden User Stories zusammensetzt |
| **Definition of Done** | Vorher festgelegte Bedingungen, unter denen eine User Story als vollständig umgesetzt gilt |

---

## User Stories

| Begriff | Definition |
|--------|-----------|
| **User Story** | Beschreibung einer Funktionalität aus Nutzerperspektive; Formulierungsschema: "Als [Persona] möchte ich [Zieldurchführung], weil [Begründung]" |
| **Story Card** | Physische oder digitale Karte zur Darstellung einer User Story; enthält Formulierungsschema, Rückseitenbeschreibung und Story Points |
| **Akzeptanzkriterien** | Bedingungen auf der Rückseite einer Story Card, die beschreiben, wann eine User Story erfüllt ist |

## Agile Entwicklungsmodelle

| Begriff | Definition |
|--------|-----------|
| **Dual Track Agile** | Arbeitsmodell mit zwei parallelen Tracks: Envisioning (UX Design/Konzept) und Delivery (Implementierung); interdisziplinäre Teams in beiden Tracks |
| **Triple Track Agile** | Erweiterung von Dual Track Agile mit drei Tracks: Envisioning, Delivery: UI Design, Delivery: Implementierung |
| **Sprint Zero (Sprint 0)** | Vorbereitender Sprint vor Beginn der Entwicklung; Designteam erarbeitet übergreifendes visuelles Erscheinungsbild und grundlegende Projektgrundlagen |
| **One Sprint Ahead** | Prinzip, nach dem das Designteam immer einen Sprint vor dem Entwicklungsteam arbeitet; Synonym für Sprint Zero / Dual Track Agile |
| **Dual Track Sprint Planning** | Sprintplanung mit getrennten Story-Point-Schätzungen für Entwicklung und Design; erhöht Planungssicherheit |

## Übergreifende Konzepte

| Begriff | Definition |
|--------|-----------|
| **Collaborative UX Design 2.0** | Übergreifendes Vorgehensmodell des im Buch beschriebenen Designprozesses; orchestriert die Zusammenarbeit von Stakeholdern in 8 Workshops von Scoping bis Delivery |
| **Problemraum** | Phase des Designprozesses, in der das Problem und der Nutzungskontext verstanden werden (Workshops: Scoping, Research, Synthese) |
| **Lösungsraum** | Phase des Designprozesses, in der Lösungen entwickelt, ausgearbeitet und validiert werden (Workshops: Ideation, Konzept, Prototyping, Validierung, Roadmap) |
| **Sprint Planning Workshop** | Workshop mit dem gesamten Team zu Beginn eines Sprints; dient zur Verfeinerung von User Stories, Aufwandsschätzung und Festlegung des Sprint-Umfangs |
