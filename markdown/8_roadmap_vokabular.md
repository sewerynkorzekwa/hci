# Vokabular – Kapitel 8: Roadmap

---

## Releaseplanung

| Begriff | Definition |
|--------|-----------|
| **Roadmap** | Dokument, das beschreibt, welche Releases in welcher Abfolge ausgeliefert werden; basiert auf der Priorisierungsmatrix |
| **Release** | Auslieferung einer neuen Version eines Produkts mit definierten Features |
| **MVP (Minimum Viable Product)** | Erstes Release mit nur den essenziellen Merkmalen, die eine spürbare Verbesserung gegenüber der bisherigen Lösung bieten; erster Schritt im Continuous Delivery |
| **Continuous Delivery** | Entwicklungsstrategie, bei der fortlaufend neue Releases mit jeweils kleinen Neuerungen ausgeliefert werden; Gegensatz zur traditionellen Entwicklung mit wenigen großen Releases pro Jahr |
| **Baseline (Ausgangswert)** | Quantitative Ausprägung einer Metrik im aktuellen System; dient als Vergleichswert für zukünftige Releases |
| **Folgerelease** | Release nach dem MVP; enthält weitere Features in Reihenfolge ihrer Priorität |

---

## Priorisierungsmatrix

| Begriff | Definition |
|--------|-----------|
| **Priorisierungsmatrix** | Werkzeug zur systematischen Gegenüberstellung von Features und ihrer Bedeutung aus verschiedenen Perspektiven (Business, Nutzerziele, Aufwand) |
| **Businessziele** | Wirtschaftliche Projektziele (z.B. Fakturierbarkeit erhöhen, Reklamationen reduzieren); bilden Zeilen der Priorisierungsmatrix |
| **Nutzerziele** | Erwarteter Einfluss einer Funktion auf das Nutzererlebnis; bilden Zeilen der Priorisierungsmatrix |
| **Gewichtung** | Punktebewertung (1–3) der Bedeutung eines Businessziels oder der Nutzerziele durch die jeweiligen Stakeholder |
| **Zwischensumme** | Summe aller Produkte aus Zeilen- und Spaltengewichtung für ein Feature; repräsentiert den kombinierten Einfluss auf Business- und Nutzerziele |
| **Gesamtpunkte** | Zwischensumme ÷ Aufwand; finale Priorität eines Features |
| **Aufwand** | Schätzung des technischen Realisierungsaufwands durch das Entwicklungsteam (1–3 Punkte) |
| **Pareto-Prinzip (80/20-Regel)** | Heuristik: 20% der Workflows decken 80% der Nutzung ab; Grundlage für die Einschränkung des MVP auf die häufigsten Anwendungsfälle |

## Metrikenboard

| Begriff | Definition |
|--------|-----------|
| **Metrikenboard** | Werkzeug zur Definition relevanter Metriken, Messmethoden und Zielwerte für Releases; Grundlage für abgestimmte Studien zur Erfolgskontrolle |
| **Metrik** | Messbarer Indikator, der eine Eigenschaft eines Produkts quantitativ ausdrückt (z.B. Effizienz, Effektivität, Zufriedenheit) |
| **Messmethode** | Art und Weise, wie eine Metrik erhoben wird (z.B. SUS-Befragung, Zeitmessung mit Log, Loganalyse) |
| **Zielwert** | Angestrebter quantitativer Wert einer Metrik nach einem definierten Release |
| **SUS (System Usability Scale)** | Standardisierter Fragebogen zur Messung der subjektiven Gebrauchstauglichkeit; 10 Fragen, 5-stufige Skala; ermöglicht Vergleich mit Benchmarkwerten |
| **Effizienz (als Metrik)** | Messung der Zeit, die Nutzende zur Bearbeitung einer definierten Aufgabe benötigen (z.B. Zeit für Leistungserfassung) |
| **Effektivität (als Metrik)** | Messung des Anteils erfolgreicher Aufgabenbearbeitungen (z.B. Anteil verrechenbarer Stunden pro Tag) |
| **Benchmarkwert** | Bekannter Vergleichswert aus publizierten Studien oder Branchendurchschnitt (z.B. SUS-Benchmark von 62 Punkten) |
